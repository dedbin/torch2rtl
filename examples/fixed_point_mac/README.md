# Умножение с накоплением в формате с фиксированной запятой (Fixed-point MAC)

## Формат

- Данные хранятся как signed int8.
- `FRAC_BITS=6`, поэтому масштаб `S=2^6=64`.
- Входы, веса и bias представлены в масштабе `S`.
- Результат умножения двух таких значений имеет масштаб `S²`.

## Арифметика

```text
acc = (bias_int << 6) + sum(input_int * weight_int)
shifted = acc >>> 6
output = saturation(shifted, -128, 127)
```

`np.rint` используется только при начальном квантовании float в целое число.
После MAC нового округления нет: аккумулятор просто сдвигается вправо
арифметически на 6 бит.

## Ширина аккумулятора

```text
одно произведение:   [-16256, 16384]
bias << 6:           [-8192, 8128]
четыре произведения: [-65024, 65536]
полный acc:          [-73216, 73664]
signed 17-bit:       [-65536, 65535]
signed 18-bit:       [-131072, 131071]
```

Полный диапазон `[-73216, 73664]` шире signed 17-bit, поэтому 17 бит
недостаточно. Signed 18-bit перекрывает его полностью, значит для текущей
конфигурации `ACC_BITS=18` достаточно.

## Overflow

Python проверяет overflow только на тех входных векторах, которые действительно были запущены.
RTL с недостаточным `ACC_BITS` не остановится с ошибкой, а получит wraparound из-за ограниченной разрядности.
Для текущих `TAPS=4`, int8 и Q8.6 безопасность 18 бит подтверждается расчётом диапазона.
Этот вывод нельзя автоматически переносить на другое количество `TAPS`: диапазон аккумулятора придётся считать заново.

## Синтез Yosys

Yosys проверяет синтезируемость MAC в generic-логике; этот результат не является отчётом LUT/DSP конкретной FPGA.
