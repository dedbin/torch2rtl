# Эталонная реализация арифметики с фиксированной запятой на C

Каталог `c_reference/` содержит независимую эталонную реализацию арифметики
`torch2rtl` на C11 без внешних зависимостей. Она принимает уже квантованные
целые значения и должна совпадать бит в бит с реализацией на Python и с RTL.

Код оформлен как библиотека отдельных операций. Это не среда выполнения
`GraphIR`, не генератор RTL или HLS и не готовый интерфейс для вызова из Python.
Библиотека входит в репозиторий с исходным кодом, но не включается в пакет
Python (`wheel`).

## Сборка и проверка

Команды из каталога `c_reference/`:

```sh
make strict
make test
make ubsan
make asan
# запустить проверки с UBSan и ASan
make sanitize
```

Цель `strict` собирает тесты на C и программу с детерминированными
псевдослучайными проверками. Компилятор получает следующие флаги:

```text
-std=c11 -Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion -Werror
```

Цель `test` запускает обе собранные программы. Цели `ubsan` и `asan` повторяют
проверки с UndefinedBehaviorSanitizer и AddressSanitizer. Для ASan задано
`ASAN_OPTIONS=detect_leaks=0`, потому что LeakSanitizer может быть недоступен в
окружении с ограничениями `ptrace` или в CI. Проверка обращений к памяти при
этом остаётся включённой. Параметр `halt_on_error=1` завершает проверку с
ошибкой при первом найденном нарушении.

Из корня репозитория можно запустить сравнительные тесты через `ctypes`:

```sh
.venv/bin/python -B -m pytest -q -p no:cacheprovider \
  --basetemp=/tmp/torch2rtl-c-reference-pytest \
  tests/test_c_reference.py
```

Тесты собирают временную динамическую библиотеку и сравнивают основные операции
`Linear`, `Conv2d`, `ReLU`, `Flatten` и `Argmax` с реализацией на Python. Для
одного MAC выполняется полный перебор форматов `B=2` и `B=3`. Для двух
последовательных сумм MAC полностью перебирается формат `B=2`. Отдельный тест
собирает весь маршрут `tiny-conv` из операций C и сравнивает все промежуточные
значения, логиты и класс. Если установлен Icarus Verilog, тот же набор входов
проверяется на RTL.

Обвязка на `ctypes` используется только в тестах и не является поддерживаемым
интерфейсом библиотеки.

## Возможности версии 1

Основные тензорные функции открытого API принимают уже квантованные значения в
массивах `int64_t` и поддерживают:

- `Linear`: вход `[in]`, веса `[out][in]`, смещение `[out]`, выход `[out]`;
- `Conv2d` без пакетного измерения: вход и выход CHW, веса OIHW, смещение O;
- `ReLU`;
- `Flatten` с сохранением порядка элементов;
- глобальный `Argmax`, который при равенстве выбирает первый максимум и
  возвращает индекс `int64_t`.

В `fixed_reference.h` также объявлены вспомогательные функции для насыщения,
возврата к исходному масштабу, масштабирования смещения, умножения, сложения и
расчёта одного выхода `Linear`. Функция `t2r_conv2d_output_shape()` отдельно
проверяет параметры свёртки и вычисляет размер выхода. `t2r_requantize()` только
возвращает значение к исходному масштабу. Насыщение выполняется отдельно через
`t2r_saturate()`. Функция `t2r_linear_one()` получает смещение как отдельное
число. Нулевое смещение для неё означает отсутствие смещения.

Допустимы только следующие конфигурации:

```text
2 <= bits <= 32
0 <= frac_bits < bits
bits < acc_bits <= 64
```

Все размеры тензоров и шаги свёртки должны быть положительными. Пустые тензоры
не поддерживаются. Дополнение `Conv2d` должно быть неотрицательным и задаётся
типом `size_t`.

Пространственный размер выхода `Conv2d` рассчитывается по формуле:

```text
floor((input + 2 * padding - kernel) / stride) + 1
```

Ядро, которое не даёт ни одного выходного элемента, считается ошибкой.

Арифметика определена так:

```text
вклад смещения          = bias_q * 2^frac_bits
накопитель              = вклад смещения + sum(input_q * weight_q)
возврат к масштабу      = floor(накопитель / 2^frac_bits)
выход                   = saturation_to_signed_bits(возврат к масштабу)
```

Библиотека проверяет масштабированное смещение, каждое произведение и каждое
промежуточное значение накопителя на соответствие знаковому диапазону
`acc_bits`. Поздняя компенсация не отменяет уже возникшее переполнение. Для
отрицательных значений используется математическое деление с округлением вниз.
Результат не зависит от того, как конкретный компилятор C выполняет правый
сдвиг знакового целого числа.

## Буферы и ошибки

Входные и выходные буферы принадлежат вызывающему коду. Библиотека не выделяет
память и не хранит скрытое глобальное состояние. Указатели на тензорные буферы
передаются вместе с числом доступных элементов или ёмкостью. Если передан
ненулевой указатель и значение `N`, вызывающий код обязан предоставить
доступный массив как минимум из `N` элементов. По обычному указателю C нельзя
определить фактический размер выделенной памяти.

Функции возвращают один из следующих статусов:

| Статус | Значение |
| --- | --- |
| `T2R_OK` | Операция выполнена успешно |
| `T2R_INVALID_ARGUMENT` | Не передан обязательный указатель, неверна конфигурация или структурный параметр |
| `T2R_DIMENSION_OVERFLOW` | Размер, число элементов или размер массива в байтах нельзя представить типом `size_t`, либо индекс `Argmax` не помещается в `int64_t` |
| `T2R_BUFFER_TOO_SMALL` | Переданное число элементов или ёмкость меньше требуемого значения |
| `T2R_VALUE_OUT_OF_RANGE` | Активация, вес или смещение не помещается в знаковый диапазон `bits` |
| `T2R_ACCUMULATOR_OVERFLOW` | Масштабированное смещение, произведение или промежуточное значение накопителя не помещается в знаковый диапазон `acc_bits` |

Проверки выполняются в фиксированном порядке:

1. обязательные указатели, основные аргументы и правила совпадения указателей;
2. конфигурация арифметики с фиксированной запятой;
3. структурные размеры и запрет нулевых размеров;
4. переполнение при расчёте размеров, числа элементов и размера массива в байтах;
5. число элементов во входных буферах и ёмкость выходного буфера;
6. правила необязательного смещения;
7. диапазоны операндов;
8. переполнение масштабированного смещения, произведений и накопителя во время вычисления.

Если проверка неприменима к конкретной функции, она пропускается. Порядок
остальных проверок не меняется.

Если функция вернула статус, отличный от `T2R_OK`, весь её выход считается
недействительным. Это относится и к уже записанной части выходного буфера, если
ошибка возникла позже.

Смещение для `t2r_linear()` и `t2r_conv2d()` можно не передавать только в
сочетании `bias == NULL && bias_count == 0`. Если `bias` не равен `NULL`,
значение `bias_count` должно точно совпадать с требуемым числом смещений.
Остальные сочетания указателя и размера считаются ошибкой.

Избыточное число доступных элементов во входе и весах, а также избыточная
ёмкость выхода допускаются и игнорируются. Если буфер меньше требуемого,
функция возвращает `T2R_BUFFER_TOO_SMALL`.

`Flatten` использует `memmove`, поэтому поддерживает разные буферы, работу на
месте и частичное перекрытие памяти. `ReLU` поддерживает разные буферы и работу
на месте с одинаковыми указателями. Частичное перекрытие для `ReLU` не входит в
контракт. Выход `Linear` и `Conv2d` не должен перекрываться со входом, весами или
смещениями. Библиотека явно обнаруживает только совпадение начальных указателей.
За отсутствие другого частичного перекрытия отвечает вызывающий код.

## Что не поддерживается

В версию 1 не входят:

- квантование значений с плавающей запятой;
- пакетная обработка, `groups` и `dilation`;
- выполнение произвольных FX DAG;
- разбор `GraphIR` или модели;
- запуск по набору данных;
- ABI для графа и рабочего буфера;
- файлы весов;
- динамическое выделение памяти;
- SIMD и многопоточность;
- генерация кода для ПЛИС;
- готовый интерфейс вызова из Python.

Код на `ctypes` в `tests/test_c_reference.py` только связывает C и Python во
время тестирования. Он не входит в открытый API.

Ускорение вычислений не проверялось в 1 версии
